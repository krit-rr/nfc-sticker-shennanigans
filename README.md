# nfc-sticker-shenanigans

NFC stickers that do things. One repo for the phone app, the website the stickers point at, and the
shared logic underneath.

| Where           | What                                                                                                                                                                                                                      |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/mobile`   | **Tap** — Expo (SDK 57) app for iOS + Android. Alarms you can only stop by tapping a sticker across the room, morning routines you check off by tapping, a Brick-style focus toggle, a sticker writer.                    |
| `apps/web`      | Next.js 16 site. Business card pages (`/c/<slug>` + `.vcf`), the page a phone without the app lands on (`/t/<id>`), a browser sticker writer (Web NFC), and the `.well-known` files that make sticker links open the app. |
| `packages/core` | `@tap/core` — the domain model: tags, actions, alarms (with nag chains and sleepyti.me sleep-cycle times), routines, cards, sticker URLs. Pure TypeScript + zod. Tested.                                                  |
| `packages/ndef` | `@tap/ndef` — NDEF encode/decode and "will this fit on an NTAG213?" math. Zero dependencies. Tested.                                                                                                                      |
| `docs/`         | [Vision](docs/vision.md) · [NFC notes](docs/nfc-notes.md) · [Alarm strategy](docs/alarm-strategy.md)                                                                                                                      |

## How a sticker works

A sticker stores one URL, `https://tap.example.com/t/<8-char id>`, plus an Android Application Record
so Android opens the app directly. The id is looked up in the app's registry, which says what the tag
does (alarm anchor, routine step, focus toggle, event log, …). Stickers are pointers, so you can
re-purpose one without rewriting it. Business-card stickers point at `/c/<slug>` instead, so any phone
opens the card page and can save the contact.

## Getting started

Prerequisites: Node ≥ 22, pnpm 9 (see the Apple Silicon note below), Xcode 26+ and/or Android Studio
for device builds.

```bash
pnpm install
pnpm check                              # lint + typecheck + tests, everywhere
pnpm web                                # Next.js at http://localhost:3000
pnpm mobile                             # Expo dev server (simulators; no NFC there)
pnpm --filter @tap/mobile ios:sim       # build + install + launch on the booted iOS simulator
pnpm --filter @tap/mobile ios:device    # development build on a real iPhone — NFC works
pnpm --filter @tap/mobile android       # development build on an Android device
```

NFC and AlarmKit are native modules, so Expo Go and the simulators can't do them. Everything else
(routines with "Simulate tap", alarm previews, card pages) works in a simulator and on the web.
`ios:sim` exists because `expo run:ios` on Xcode 27 mistakes the simulator for a physical device and
asks for a signing certificate; the script drives `xcodebuild` directly (see `apps/mobile/README.md`).

## Conventions

- `packages/*` are consumed as TypeScript source (`main` points at `src/index.ts`), no build step. Next
  compiles them through `transpilePackages`; Metro handles them natively.
- Add Expo dependencies with `pnpm --filter @tap/mobile exec expo install <pkg>` so SDK-compatible
  versions are picked. Everything else: `pnpm --filter <pkg> add <dep>`.
- `apps/mobile/ios` and `apps/mobile/android` are generated by `expo prebuild` and git-ignored. Native
  behaviour is configured in `app.json` and config plugins, never by editing those folders.
- Domain logic lives in `@tap/core` and is unit-tested with vitest; apps stay thin.

## Before shipping

- Replace the placeholder host `tap.example.com` in `apps/mobile/app.json` (`extra.tagBaseUrl`,
  `ios.associatedDomains`, `android.intentFilters`) and `apps/web/src/lib/site.ts`.
- Replace the placeholder ids `com.example.tap` (`app.json` and `apps/web/src/lib/site.ts`).
- Deploy the web app with `APPLE_TEAM_ID` and `ANDROID_SHA256_CERT_FINGERPRINT` set so universal links
  and app links verify.

## Note for Apple Silicon Macs

The pnpm binary installed at `~/Library/pnpm/pnpm` on this machine is an x86_64 build running under
Rosetta while Node is arm64, so pnpm would install x64 native bindings that Node cannot load. The root
`package.json` therefore lists `pnpm.supportedArchitectures.cpu: ["current", "arm64"]`, which installs
both. Reinstall pnpm natively and that setting can go:

```bash
curl -fsSL https://get.pnpm.io/install.sh | sh -
```
